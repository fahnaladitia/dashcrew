# v0.8: clear messages, and `init` without dead ends

Tier: standard, as two PRs. Both change CLI output (transcripts rewritten and reviewed); PR 1 also changes the generated testing rule of projects on `platform: other`.

Items of the v0.8.0 "Launch-ready" milestone in `docs/ROADMAP.md` ("Install and `init`"). Signal to reach: a fresh `init` + `sync` + `doctor` prints no warning.

## Reproduced on `main` (2026-11-17)

```
$ dashcrew sync            # in a folder without .ai/
No .ai/project.yaml in /tmp/x/s/.. Run dashcrew init first.

$ dashcrew doctor          # platform: other, all three agents
ok    mcp             defined:
ok    codex-mcp       defined:  (by the user, outside the dashcrew block)
ok    codex-skills-budget22 skills, list 3822 of 8000 characters
ok    antigravity-hookPreToolUse guard hook present under dashcrew-guard
ok    antigravity-roles2 roles, every tool name known

AGENTS.md (platform: other, analyze: `ruff check .`):
- Scope runs to the diff: `ruff check . <changed paths>` and `pytest <covering test files>`.

$ dashcrew init -y         # a Go module
  platform: none of flutter (pubspec.yaml)
  tip: this is a Go module; dashcrew platform new go writes a Go platform for this repo to edit, then run dashcrew sync
No platform detected. Rerun without --yes to declare platform: other and its commands.   (exit 1)

$ dashcrew init            # interactive, a Go module: asks `detect` with no default until it gives up

$ dashcrew doctor          # fresh Flutter or Go project, empty HOME
warn  skills          not found locally (install, or ignore if a plugin provides them): idea-refine
```

## PR 1: messages

1. **Paths**: `absolute` in `cmd/dashcrew/main.go` returns `cwd + "/" + path` uncleaned, so `-p .` is `…/s/.`, and the sentence's full stop makes it read `…/s/..`. It returns `filepath.Clean` of the joined path.
2. **Status table**: `printChecks` pads IDs to 16 columns, and `antigravity-hook` (16), `antigravity-roles` (17) and `codex-skills-budget` (19) run into their detail. The column is the longest ID of the report plus two, at least 16, so a report without long IDs prints as today.
3. **MCP checks with nothing to define**: `mcp`, `codex-mcp` and `antigravity-mcp` say `no MCP servers to define` instead of `defined:` with an empty list.
4. **Testing rule** (`core/rules/testing.md`, used by `platform: other` and project platforms): `` `{{analyze}} <changed paths>` `` becomes "run `{{analyze}}` on the changed paths and `{{test_scoped}}` on the covering test files", which reads right whether the command already names a path or not. Flutter keeps its own wording. Goldens of `platform: other` and project-platform samples change by that line.

## PR 2: `init`

1. **A Go module gets Go.** When `go.mod` is at the root and no built-in platform matches, `init` offers `go` first among the platform choices and makes it the default; `init -y` takes it. Choosing it runs what `dashcrew platform new go` runs (writes `.ai/platforms/go/` and `.ai/project.yaml`), so the help text's "Writes nothing else" gains "except a starter platform you choose". The tip line goes.
2. **`platform: other` proposes its detect files.** `init` looks for common root markers (`pyproject.toml`, `setup.py`, `package.json`, `Cargo.toml`, `pom.xml`, `build.gradle`, `build.gradle.kts`, `Gemfile`, `composer.json`, `mix.exs`, `Makefile`) and offers the ones present as the default answer to `detect`. Commands get no guessed default: a wrong test command is worse than a question.
3. **Detected first.** Before any prompt, `init` prints what it found: the marker files, and the stack options it detected, as it does for Flutter.
4. **No question loop.** A required answer left empty is asked once more, then `init` stops with exit 1 and the message it prints today.
5. **Optional outside skills are not a warning.** The `skills` check lists skills the rules mention only "when installed" (`idea-refine`, `spec-driven-development`, `source-driven-development`, `flutter-add-integration-test`) as `ok … optional, not installed: idea-refine`. A missing dashcrew skill still fails, and a required project skill still warns.

Tests first in `internal/initproject`, `internal/doctor` and the transcripts: a Go module with `-y` and interactively, `other` with a `pyproject.toml`, an empty answer twice, and a fresh Flutter and Go project whose `doctor` has no `warn` line (empty HOME, guard binary stubbed as in the existing doctor tests).

## Not in these PRs

- **Go as a built-in platform** (`platforms/go` in the catalog instead of a starter copied into the repo). That changes the output layout of every Go project, so it is a large change with its own plan. PR 2 already removes the dead end, which is what visitors hit.
