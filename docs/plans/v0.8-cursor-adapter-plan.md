# v0.8: Cursor adapter (rules, skills, subagents, MCP and a fail-closed guard hook)

Tier: large. New adapter, new agent value in `project.yaml`, new guard input shape, new golden sample, a raised guard minimum for projects that list `cursor`.

Item of the v0.8.0 "Launch-ready" milestone in `docs/ROADMAP.md`: "Adapter for Cursor: rules plus the guard hook, golden-tested, covered by the doctor probe. Spike the hook first to confirm it can fail closed."

## What the Cursor docs say (read 2026-11-17)

Sources: https://cursor.com/docs/hooks, /docs/context/rules, /docs/context/skills, /docs/context/subagents, /docs/context/mcp, /docs/reference/third-party-hooks, /docs/cli/using.

- **Hooks file**: project `<root>/.cursor/hooks.json`, `{"version": 1, "hooks": {"<event>": [entry]}}`. An entry has `command`, `type`, `timeout` (seconds), `matcher` (regex), `failClosed`. Hooks of every source (enterprise, team, project, user, plugins) run; `deny` wins over `ask`, `ask` over `allow`.
- **Events that can block** a tool call: `preToolUse` (matchers `Shell`, `Read`, `Write`, `Grep`, `Delete`, `Task`, `MCP:<tool>`), `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `subagentStart`. There is no `beforeFileEdit`: `preToolUse` with `Write` is the only gate before a write.
- **Input**: common fields `hook_event_name`, `cursor_version`, `conversation_id`, `workspace_roots`, …; `preToolUse` adds `tool_name`, `tool_input` (`Shell`: `{command, working_directory}`), `cwd`; `beforeShellExecution` has top-level `command` and `cwd`. `tool_input` of `Write` and `Delete` is not documented.
- **Output**: `{"permission": "allow"|"deny"|"ask", "user_message", "agent_message"}`; for `preToolUse` `ask` is not enforced. Exit 2 blocks like `deny`; any other non-zero exit lets the call through.
- **Failure**: fail open by default. `"failClosed": true` makes a crash, timeout, non-zero exit or no output block. Invalid JSON, or JSON that does not match the schema, blocks even without it.
- **Where it runs**: project hooks run from the project root; `CURSOR_PROJECT_DIR` (and `CLAUDE_PROJECT_DIR` as an alias) are set. Windows runs hooks through PowerShell. Project hooks need a trusted workspace; no per-hook approval.
- **Claude Code hooks run in Cursor too**: Cursor reads `.claude/settings.json` hooks ("Include Third-Party Plugins, Skills, and Other Configs", on by default), maps `Bash` to `Shell` and `Edit` to `Write`; exit 2 blocks, other failures are fail open.
- **Rules**: Cursor reads `AGENTS.md` at the root and in subfolders; `.cursor/rules/*.mdc` (`description`, `globs`, `alwaysApply`) is optional.
- **Skills**: read from `.agents/skills/` (and `.cursor/skills/`, `.claude/skills/`); front matter `name` (must match the folder) and `description`.
- **Subagents**: `.cursor/agents/<name>.md`, also `.claude/agents/` and `.codex/agents/`; front matter `name`, `description`, `model` (`inherit`), `readonly`, `is_background`. No `tools` field.
- **MCP**: `.cursor/mcp.json`, `{"mcpServers": {"<name>": {"command", "args", "env"}}}`.
- **CLI** (`agent`): same rules, `AGENTS.md` and `mcp.json`. Which hook events the CLI fires is not documented; a forum report says hooks did not fire on Linux in 2026.08.11.

## A gap that exists today

The guard does not read Cursor's input. Fed to `dashcrew guard` with `expense_tracker`'s policy (built from `main`, 2026-11-17):

| Input | Exit |
|---|---|
| `preToolUse`, `tool_name: "Shell"`, `tool_input.command: "git push"` | 0 (allowed) |
| `beforeShellExecution`, `command: "git push"` | 0 (allowed) |
| Claude Code `Bash`, `git push` (control) | 2 (blocked) |

`FromHook` knows `Bash` and Codex's shell tools, not `Shell` (`internal/guard/event.go:85`), so every other tool name is `Other` and allowed. A project that lists `claude-code` and is opened in Cursor runs the Claude Code guard hook through the third-party path; if Cursor sends its own input shape there, which the "maps Bash to Shell" sentence suggests, the guard lets every call through. The spike confirms which shape arrives.

Reading Cursor's input in the guard closes this for every `claude-code` project, with or without the adapter. It can ship first, as v0.7.1 (see Decisions).

## Spike (before any adapter code)

Needs a Cursor install with agent access, on `expense_tracker` (Flutter, `claude-code`, `codex`, `antigravity`; branch `chore/ai-toolkit-full-dashcrew`). Nothing is committed there.

1. **Capture real inputs.** A project `.cursor/hooks.json` whose `preToolUse` (matcher `*`), `beforeShellExecution` and `subagentStart` hooks copy stdin to `/tmp/cursor-hook/<event>-<n>.json` and print `{"permission":"allow"}`. Ask the agent to run a shell command, write a file, edit a file, delete a file, and start a subagent. Record:
   - `tool_input` of `Write` (and of an edit, if it is also `Write`) and of `Delete`;
   - whether a subagent's tool calls carry its name (needed for role limits);
   - which input shape the `.claude/settings.json` guard hook receives in Cursor.
2. **Allowed call.** With the guard as the hook: does exit 0 with no output let the call through, or does Cursor read it as "no output" and block? Is `{"permission":"allow"}` needed, and does it approve a command Cursor would otherwise ask about? (The Antigravity lesson: `allow` must not approve anything.)
3. **Blocked call.** `git push`, `bash -c "git push"`, `env git push`, and a write that imports `package:posthog_flutter`: each blocked, and the agent sees the reason.
4. **Fail closed.** With `"failClosed": true`: shim removed (exit 127), dashcrew off PATH (shim refuses), guard that sleeps past `timeout`. Each must block. Then the same without `failClosed`, to write down what users of the third-party path get.
5. **CLI.** Repeat 3 and 4 in `agent` on macOS.

If step 4 does not block, the adapter stops here: the roadmap item becomes "Cursor rules only, no guard claim", and the launch pitch changes.

## Design

### Agent list in one place

New package `internal/agents`: the agent values in message order (`claude-code`, `codex`, `antigravity`, `cursor`), and for each one whether `me sync` writes for it. `profile.SupportedAgents`, `adapters.SupportedAdapters` and `me.Agents` read from it. The per-agent switches in `doctor`, `budget`, `sync` and `guard/malformed.go` stay as switches, with a test that each one handles every agent.

### Guard

- `FromHook` reads Cursor's input, told apart by `cursor_version`:
  - `preToolUse` `Shell` → shell event from `tool_input.command`;
  - `beforeShellExecution` → shell event from top-level `command`;
  - `preToolUse` `Write` and `Delete` → write and delete events, with the field names the spike records.
- `HookResponse` answers Cursor with a JSON permission on stdout: `deny` with the reason in `user_message` and `agent_message`. For an allowed call it prints what the spike shows lets the call through without approving it.
- The shim's `refuse` prints the same `deny` JSON for Cursor input; exit 2 stays as the fallback.
- `malformed.go` names `cursor` in the log.
- New `version.CursorGuardMinimum` (the release that ships this; 0.8.0, or 0.7.1 if the guard part ships first). `guardMinimum` raises the lock's minimum when `cursor` is listed, as for Antigravity.

### Adapter `cursor`

- **Files**:
  - skills to `.agents/skills/<name>/SKILL.md` (`AgentsSkillFile`, shared with Codex and Antigravity; `SkillFile("cursor", …)` returns that path);
  - roles to `.cursor/agents/<role>.md`: `name`, `description`, `model: inherit`, `readonly: true` for the `read` capability. `write-plans` cannot be limited to the plans folder, so that limit stays an instruction, as for Antigravity.
  - No `.cursor/rules/`: Cursor reads `AGENTS.md`, which sync already writes.
- **Merge**:
  - `.cursor/hooks.json`: keep `version`, put one dashcrew entry in `hooks.preToolUse` (replacing the entry that calls `.ai/bin/guard`, as `replaceGuardEntry` does), keep every other entry:

    ```json
    {"matcher": "^(Shell|Write|Delete)$", "command": "<CursorGuardCommand>", "timeout": 30, "failClosed": true}
    ```

    `CursorGuardCommand` runs the shim from `$CURSOR_PROJECT_DIR`, falling back to the working folder (the project root). Whether `beforeShellExecution` is needed besides `preToolUse` `Shell` is decided by the spike; one event is preferred so the guard runs once per call.
  - `.cursor/mcp.json`: the platform servers and the knowledge server through `MergeJSONMcpServers`.
- **Double run**: a project with `claude-code` and `cursor` runs the guard twice per call in Cursor (its own hook, fail closed, and the Claude Code one, fail open). `deny` wins, so the result is right; the cost is one more process. Documented, not fixed.

### Doctor and check

- `cursor-hook`: the dashcrew entry is present, matches what sync writes and has `failClosed: true`. Part of `HookChecks`, so `dashcrew check` runs it in CI.
- `cursor-mcp`: the servers are in `.cursor/mcp.json`.
- Budget: `AGENTS.md`, plus `.cursor/rules/*.mdc` with `alwaysApply: true` the user added.

### Out of scope

- `me sync` for Cursor (user rules live in Cursor's settings, not in a file); `me.Agents` stays without `cursor`.
- Windows (PowerShell hooks): moves with the Windows decision.
- Cursor commands (`.cursor/commands/`): skills replace them in Cursor's docs.
