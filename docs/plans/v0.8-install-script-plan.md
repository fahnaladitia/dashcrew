# v0.8: install.sh and install smoke tests

Tier: standard. A new shipped file (`install.sh`), a test for it, a CI job and the README install section. No generated project file changes.

Item of the v0.8.0 "Launch-ready" milestone in `docs/ROADMAP.md`: "An `install.sh` that downloads the release archive and checks `checksums.txt`; install smoke tests in CI (brew, `go install`, script)."

## Goal

One command for a visitor without Homebrew or Go:

```bash
curl -fsSL https://raw.githubusercontent.com/fahnaladitia/dashcrew/main/install.sh | sh
```

It installs the latest final release, or the one a team pins, and never installs an archive whose checksum it could not check.

## Today

- Releases (goreleaser): `dashcrew_<version>_<os>_<arch>.tar.gz` for darwin and linux, `.zip` for windows, amd64 and arm64, plus `checksums.txt` (SHA-256) and a build provenance attestation.
- `https://github.com/fahnaladitia/dashcrew/releases/latest` redirects to the latest final release (`v0.6.0` today); pre-releases are never "Latest".
- README installs through `brew` or `go install` only. CI builds a goreleaser snapshot and runs an upgrade check, but never installs a published release.

## Design

### `install.sh` (repository root, POSIX `sh`)

1. **Platform**: `uname -s` → `darwin` or `linux`; `uname -m` → `amd64` (`x86_64`, `amd64`) or `arm64` (`arm64`, `aarch64`). Anything else stops with the `go install` command. Windows stops with the same message, as the guard shim needs `sh` (see the Windows decision).
2. **Version**: `DASHCREW_VERSION` (`0.6.0` or `v0.6.0`), else the tag `releases/latest` redirects to, read from the final URL with `curl -w '%{url_effective}'` or `wget`'s `Location`, so no GitHub API call and no rate limit. A version that is not `major.minor.patch[-pre]` stops.
3. **Download** the archive and `checksums.txt` into a `mktemp -d` folder, removed on exit. `curl -fsSL`, else `wget -q`; neither stops.
4. **Verify**: the archive's line in `checksums.txt` must exist, and `sha256sum` (else `shasum -a 256`) must print the same hash. No line, no hashing tool or a different hash stops before anything is installed. There is no flag to skip it.
5. **Install** into `DASHCREW_INSTALL_DIR`, else `$HOME/.local/bin`, created when missing; no `sudo`. The binary is copied next to its target and renamed over it, so a running `dashcrew` (a guard call) never sees half a file.
6. **Check**: the installed binary's `--version` must report the version installed; otherwise it stops and says so.
7. **Report**: the path and version, a `PATH` line to add when the folder is not on `PATH`, and when an earlier `dashcrew` comes first on `PATH`, its path, since the guard shim runs that one.

`DASHCREW_RELEASES_URL` (default `https://github.com/fahnaladitia/dashcrew/releases`) points the script at a mirror; the tests use it for a local server. Verification still applies.

Provenance: the README adds `gh attestation verify <archive> -R fahnaladitia/dashcrew` for anyone who wants more than the checksum; the script does not need `gh`.

### Tests

`install_test.go` at the repository root runs `install.sh` with `sh` against an `httptest` server that serves a fake release: a `tar.gz` holding a `dashcrew` script that prints `dashcrew 9.9.9`, `checksums.txt`, and `/releases/latest` redirecting to `/releases/tag/v9.9.9`. Cases:

- latest: installs into a temp `DASHCREW_INSTALL_DIR`, prints the version;
- pinned `DASHCREW_VERSION=v9.9.8`, with and without the `v`;
- a wrong hash, an archive missing from `checksums.txt`, a missing `checksums.txt`: each fails and leaves the install folder empty;
- a binary that reports another version fails;
- an existing `dashcrew` in the folder is replaced, not left half written.

Skipped on Windows, like the shim tests.

### CI

New job `install` in `ci.yaml`, matrix `ubuntu-latest` and `macos-latest`:

- **script**: on every PR and push, `sh install.sh` from the checkout against the real latest release, then `dashcrew --version`;
- **brew** (macOS) and **go install** (both): on the daily schedule and a manual run only, since they test what is already published and a broken tap must not block unrelated PRs.

### README

The install section gains the script line first, with `DASHCREW_VERSION` for pinning and the checksum note; `brew` and `go install` stay.

## Out of scope

- Windows (`install.ps1`): waits for the Windows decision.
- Serving the script from a short domain.
