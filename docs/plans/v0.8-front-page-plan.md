## The new README (under 150 lines)

1. **Hero**: one sentence, "One source of rules, skills and guard hooks for every AI coding agent your team uses. One Go binary, any stack.", then badges (CI, latest release, license) and the not-affiliated line.
2. **Demo**: until the GIF is recorded, a text block of a real blocked call, produced by running `dashcrew guard` on a Claude Code hook payload for `bash -c "git push origin main"`. The GIF replaces it later; no broken image link ships.
3. **Why** (three bullets, the team layer):
   - one guard policy for every agent: the same git, formatter and read-only rules in Claude Code, Codex and Antigravity, nested shells unwrapped, failing closed when dashcrew is missing;
   - a lock and a drift check in CI: `dashcrew check` fails a PR whose toolkit was edited by hand or is out of date, and lints its commits;
   - team and personal profiles: the repo decides the rules, each member's `me.yaml` changes only how agents work with them.
4. **Quickstart**: the three install lines, then `init`, `sync`, `doctor` with one line each on what they do.
5. **What `sync` writes**: the agent-by-file table, as today.
6. **The guard, honestly**: what it blocks in five bullets, then "it prevents accidents, not a determined attacker; the known misses are listed in docs/guard.md".
7. **Compared with**: rulesync, Ruler and hand-written guard hooks. Every cell is checked against their current README or docs before merge, and the table says where they are ahead (both support far more agents). Draft rows: runtime; agents supported; rules, skills, subagents and MCP; a shipped guard policy with nested-shell unwrapping; a lock and a CI check for hand edits; personal profiles; commit lint. rulesync generates `hooks` and `permissions` config, so its cell reads "hook config you write", not "no".
8. **Status**: the agents supported today and run end to end, and Cursor as planned.
9. **Docs** (the index below), then Security, Contributing, License, one line each.
